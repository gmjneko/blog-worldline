# Worldline 视觉设计系统

本文档定义 Worldline 博客使用的视觉语言、设计令牌、布局规则与交互约束。页面实现应优先遵循本文档和 `src/ui` 中已经存在的组件，而不是在页面内重新创造一套样式。

## 1. 设计定位

Worldline 的视觉风格可以概括为：

> 终端工具美学 + 瑞士网格排版 + 轻量粗野主义。

它不是传统的“黑客霓虹风”，也不是带有大量渐变、玻璃和阴影的 SaaS 营销风格。它通过严格网格、等宽字体、有限色彩、细边框和大留白建立秩序感。

页面应该像技术文档、终端界面与独立出版物的结合：安静、准确、信息优先。

## 2. 设计目标

- 让文章、代码和观点成为视觉焦点。
- 通过一致的边界和间距形成稳定阅读节奏。
- 保持工具感，但不牺牲中文长文阅读体验。
- 让桌面端和移动端共享同一种视觉语言。
- 组件默认具备可访问性、键盘操作和暗色模式支持。
- 用少量可复用规则覆盖大多数页面，而不是为每个页面单独设计。

## 3. 非目标

以下方向不属于本设计系统：

- 大面积紫色、蓝色或彩色渐变。
- 霓虹光晕、大面积玻璃拟态和无语义的背景模糊。常驻导航可以使用克制的半透明模糊，以保持滚动时的层级。
- 大量悬浮卡片、厚重阴影和三维效果。
- 超大圆角、胶囊式布局和玩具化控件。
- 多套互相竞争的强调色。
- 夸张视差、持续漂浮或弹跳动画。
- 为营销文案牺牲信息密度和可读性。

## 4. 核心原则

### 4.1 单色优先

主要界面只使用暖白、近黑和灰阶。强调通过字重、边线、间距和明暗关系完成。

淡黄色 `--wl-color-interactive-soft` 只用于文本选择、轻量提示或非常有限的交互强调，不应成为大面积品牌色。

### 4.2 网格先于装饰

页面、区块和组件应共享同一组左右边界。分区优先使用 `1px` 细线，不使用独立悬浮卡片制造层级。

### 4.3 内容先于容器

不要因为存在一组内容就自动添加卡片。只有当组件拥有明确状态、边界或交互含义时才使用容器。

### 4.4 排版就是界面

等宽字体、稳定行高和有限字号共同承担大部分视觉表达。不要依靠多个装饰字体或夸张字号制造“设计感”。

### 4.5 克制交互

交互状态主要通过以下方式表达：

- 文本颜色变化。
- `1px` 或 `2px` 边线变化。
- 浅色背景变化。
- `160ms` 左右的短过渡。

避免大范围位移、缩放和弹性动画。

## 5. 设计令牌

设计令牌位于：

```text
src/ui/styles/tokens.css
```

所有通用组件必须使用 `--wl-*` 变量。页面不应直接复制令牌值；只有真正的页面专属效果才可以使用局部值。

### 5.1 颜色

| 令牌 | 亮色模式 | 用途 |
| --- | --- | --- |
| `--wl-color-background` | `hsl(0 20% 99%)` | 页面和主要容器背景 |
| `--wl-color-background-weak` | `hsl(0 8% 97%)` | Tabs、代码块和弱表面 |
| `--wl-color-background-strong` | `hsl(0 5% 12%)` | 主按钮、强对比区域 |
| `--wl-color-background-strong-hover` | `hsl(0 5% 18%)` | 强背景悬停状态 |
| `--wl-color-interactive-soft` | `hsl(62 84% 88%)` | 轻强调和文本选择 |
| `--wl-color-text` | `hsl(0 1% 32%)` | 正文和普通说明 |
| `--wl-color-text-strong` | `hsl(0 5% 12%)` | 标题、重要文字和链接 |
| `--wl-color-text-weak` | `hsl(0 1% 60%)` | 元信息、次要标签和占位信息 |
| `--wl-color-text-weaker` | `hsl(30 2% 81%)` | 图形纹理和非常弱的内容 |
| `--wl-color-border` | `hsl(0 100% 3% / 12%)` | 全局细边框 |

暗色模式通过 `prefers-color-scheme: dark` 自动切换令牌。组件中禁止使用“亮色模式专属”的硬编码颜色，终端类刻意深色组件除外。

### 5.2 字体

全站基础字体：

```css
font-family: var(--wl-font-mono), var(--wl-font-cjk);
```

等宽字体栈（拉丁字符）：

```text
IBM Plex Mono
ui-monospace
SFMono-Regular
Consolas
Liberation Mono
monospace
```

中文字符由 sans-serif 栈回退渲染：

```text
PingFang SC
Microsoft YaHei
Noto Sans CJK SC
sans-serif
```

拉丁与代码保持等宽，中文回退到系统无衬线字体（macOS 苹方、Windows 雅黑）。正式选择 Web Font 时，需要同时检查：

- 中文是否保持清晰而不过于机械。
- 拉丁字符和代码是否具有明确的 `0/O`、`1/l/I` 区分。
- 常规字重和粗体是否都可用。
- 字体许可证是否允许 Web 分发。

### 5.3 字号与行高

- 基础字号：`16px`。
- 移动端正文建议：`15px`。
- 首页或大型页面主标题：桌面端 `38px / 1.5`，移动端 `22px / 1.5`。
- 普通区块标题：`16px / 1.5 / 700`。
- 正文行高：界面文本 `1.5`，说明和长文本 `1.8–2`。
- 元信息和图注：`12–13px`。

不建议同时存在过多字号。视觉层级优先通过字重、留白和颜色完成。

### 5.4 页面尺寸

| 令牌 | 默认值 | 用途 |
| --- | --- | --- |
| `--wl-shell-width` | `1080px` | 页面外框最大宽度 |
| `--wl-header-height` | `80px` | 顶部导航高度 |
| `--wl-page-padding` | `80px` | 桌面端区块左右留白 |
| `--wl-section-padding-y` | `64px` | 普通区块上下留白 |
| `--wl-hero-padding-y` | `96px` | Hero 区域上下留白 |

`60rem` 以下：

- 左右留白调整为 `24px`。
- 普通区块上下留白调整为 `48px`。
- Hero 上下留白调整为 `48px`。

### 5.5 间距

间距基于 `4px` 网格：

```text
4, 8, 12, 16, 20, 24, 32, 40, 48, 64
```

对应令牌为 `--wl-space-1` 至 `--wl-space-16`。

推荐规则：

- 控件内部间距：`8–16px`。
- 标题与说明：`8–12px`。
- 同一信息组：`16–24px`。
- 组件之间：`24–40px`。
- 页面区块之间：由 `Section` 统一处理。

### 5.6 圆角

| 令牌 | 数值 | 用途 |
| --- | --- | --- |
| `--wl-radius-sm` | `3px` | 小型标签和行内元素 |
| `--wl-radius-md` | `5px` | 按钮、代码块和输入控件 |
| `--wl-radius-lg` | `8px` | 较大但仍克制的容器 |

页面中通常使用 `3–6px`。除非存在明确的产品需求，不增加更大的圆角。

## 6. 布局规范

### 6.1 页面外框

所有主要页面应优先由 `PageShell` 包裹：

- 桌面端最大宽度 `1080px`。
- 使用左右 `1px` 边线形成“文档纸张”边界。
- `65rem` 以下移除左右边线，让内容充分使用窄屏宽度。

### 6.2 区块

使用 `Section` 建立页面节奏：

- 区块之间由顶部细线分隔。
- 普通区块不额外添加阴影。
- Hero 使用更大的上下留白和主标题字号。
- `split` 变体用于左侧说明、右侧操作的收尾区域。

### 6.3 长文章

虽然外框最大宽度为 `1080px`，正文不应铺满整个外框。

博客文章建议：

- 正文列宽 `680–760px`。
- 可选目录或元信息占据剩余空间。
- 代码块可以适度突破正文列，但不得超出页面外框。
- 中文正文使用 `1.8` 左右行高。
- 段落之间使用稳定间距，不使用首行缩进和段间距混合规则。

文章正文可以使用全局 `.wl-prose` 类作为起点。

## 7. 边框与表面

- 默认边框：`1px solid var(--wl-color-border)`。
- Tabs 选中线：`2px solid var(--wl-color-text-strong)`。
- 不使用发光边框。
- 普通内容区域使用页面背景。
- 代码、Tabs 和弱状态区域使用 `--wl-color-background-weak`。
- 主按钮使用 `--wl-color-background-strong`。
- 阴影默认关闭；只有浮层、下拉菜单等真正离开文档流的组件才允许使用轻微阴影。

## 8. 图形与媒体

推荐图形：

- 细线图。
- 网点和斜线纹理。
- 单色柱状图。
- 终端截图和代码界面。
- 带编号的图注，如 `图 1.`、`FIG. 01`。

图片和视频应：

- 与页面网格对齐。
- 尽量使用完整宽度或明确列宽。
- 避免悬浮在页面中央的营销卡片感。
- 提供替代文本或适当的装饰性标记。

## 9. 按钮和链接

### 主按钮

- 深色背景、浅色文字。
- `4–5px` 圆角。
- 通常带一个简单方向箭头。
- 同一视口内避免出现多个竞争性的主按钮。

### 次按钮

- 页面背景、细边框、深色文字。
- 悬停时切换到弱背景。

### 普通链接

- 默认不做成按钮。
- 使用下划线、底边线或文字颜色变化表达状态。
- 不使用彩色链接破坏单色系统，除非语义要求明显警告或错误。

## 10. 响应式规则

当前组件库使用以下关键断点：

| 断点 | 行为 |
| --- | --- |
| `65rem` | 页面外框移除左右边线 |
| `60rem` | 页面留白和区块留白缩小，部分桌面布局收紧 |
| `40rem` | 切换移动导航，多列内容变为单列 |
| `24rem` | Tabs 与终端内容进一步压缩 |

响应式实现原则：

- 优先改变布局，不缩放整个页面。
- 保留 `24px` 左右安全留白。
- 不隐藏文章核心内容。
- 横向滚动只允许出现在 Tabs、表格和代码块等合理区域。
- 页面本身不得产生横向滚动条。

## 11. 暗色模式

暗色模式默认跟随系统偏好，不在组件中维护第二套独立 class。

暗色模式要求：

- 保持原有信息层级，而不是简单反色。
- 边框仍应克制，不变成高亮白线。
- 主要按钮在暗色模式中自动反转为浅背景、深文字。
- 终端组件保持其专用深色主题。
- 图形纹理继续使用弱对比颜色。

## 12. 动效

- 常用过渡时长：`160ms`。
- 只对颜色、背景、边框和短距离变换使用过渡。
- 支持 `prefers-reduced-motion: reduce`。
- 不使用持续循环动效作为背景装饰。
- 动画不能阻碍阅读或改变内容位置。

## 13. 可访问性

所有页面和组件必须遵循：

- 使用语义化的 `header`、`nav`、`main`、`section`、`footer`。
- 页面标题层级连续，不跳过必要层级。
- 所有交互元素可通过键盘操作。
- 使用明显的 `:focus-visible` 焦点轮廓。
- 图标按钮必须提供 `aria-label`。
- Tabs 必须维护 `tablist`、`tab`、`tabpanel` 关系。
- 不能只通过颜色表达选中、错误或成功状态。
- 正文和背景需要保持足够对比度。
- 尊重系统的减少动态效果偏好。

## 14. 文案语气

文案应像清晰的技术说明，而不是广告：

- 使用短句和明确动词。
- 避免“颠覆、革命、极致、重新定义”等空泛词汇。
- 标题可以有观点，但正文必须解释观点。
- 元信息简短、稳定、可扫描。
- 技术内容可使用 `[*]`、`01.`、`FIG.` 等终端或出版物标记，但不要在每个位置重复使用。

## 15. 博客页面应用规则

博客页面只承担文章浏览，不混入随笔、项目或关于介绍区块：

- 页面主标题使用 `POSTS`。
- 分类作为文章属性，由 `content/posts` 中的目录配置生成。
- 默认显示全部文章，分类筛选位于文章列表上方。
- 文章卡片展示发布日期、阅读时间、分类、标题和描述。
- 缩略图使用固定容器、`object-fit: cover` 和可配置焦点。
- 文章详情保持窄正文宽度，并使用 `.wl-prose` 作为排版基础。
- 内容结构和 Front Matter 规则见 `doc/content.md`。

业务组件可以组合通用组件库，但应继续使用现有令牌，不应创建另一套颜色、间距或按钮样式。

## 16. Do / Don't

### Do

- 使用 `PageShell` 和 `Section` 保持网格一致。
- 从 `src/ui` 统一导入组件。
- 使用设计令牌调整视觉参数。
- 优先使用已有组件的 props 和变体。
- 将页面专属布局保留在页面 CSS 中。
- 在桌面端、移动端和暗色模式下检查页面。

### Don't

- 在页面中复制组件库 CSS。
- 为单个页面重新定义相同含义的颜色变量。
- 使用大圆角、厚阴影和渐变破坏整体语言。
- 把所有内容放进卡片。
- 为了视觉对称牺牲文章可读宽度。
- 添加不能使用键盘操作的自定义控件。

## 17. 页面验收清单

提交新页面前检查：

- [ ] 页面使用统一组件入口 `src/ui`。
- [ ] 外框、区块和正文列宽符合规范。
- [ ] 没有页面级横向滚动。
- [ ] 标题层级正确。
- [ ] 所有按钮和链接都有明确用途。
- [ ] 键盘可以完成主要操作。
- [ ] 焦点状态清晰可见。
- [ ] 移动端布局没有依赖 hover。
- [ ] 暗色模式仍然可读。
- [ ] 动效尊重减少动态效果设置。
- [ ] 没有引入不必要的颜色、阴影和大圆角。

## 18. 代码位置

```text
src/ui/styles/tokens.css      设计令牌
src/ui/styles/reset.css       全局基础规则
src/ui/styles/typography.css  长文本排版
src/ui/components/            通用内容和交互组件
src/ui/layout/                页面布局组件
src/ui/index.ts               统一导出入口
```

组件的具体 API 和使用方式见根目录的 `UI_COMPONENTS.md`。
